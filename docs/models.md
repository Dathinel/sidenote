# Meeting models

The built-in Rust directory is in `src/core/model_catalog_data.rs`. It is never fetched at runtime. The only provisional defaults are `PROVISIONAL_DEFAULT_IDS` in `model_catalog.rs`; evaluation owns their eventual selection. Downloads are explicit and independent of Hex dictation.

Metadata was checked through the Hugging Face models API (`?blobs=true`) on 2026-11-09. Every download pins the returned commit. LFS SHA-256 and byte counts come from that API. The small non-LFS token and label files were fetched at the pinned revision and hashed locally. IndicConformer uses the shared root vocabulary, not an English vocabulary. Swift uses its encoder, decoder and tokens only: the pinned publisher card explicitly says the external `.weights` files are obsolete.

Five IndicConformer CTC exports use MIT per the publisher's per-family licence table. Swift and Anuvani use Apache-2.0. Anuvani requires the publisher's patched sherpa-onnx 1.13.8, documented on its pinned source page; installing it does not imply compatibility with unpatched sherpa. No model code or inference runtime is downloaded or executed. SpeechBrain was excluded because the research points to PyTorch checkpoints, not verified sherpa-onnx exports. Nemotron is a reference to Hex's existing catalogue and has no Sidenote download action.

The advisory minimum RAM field is `Option<u32>`. Local evaluation measured a maximum process peak RSS of 761,663,488 bytes for IndicConformer Hindi and 522,473,472 bytes for Swift across seven full-clip runs each. The catalogue rounds these up to 762 MB and 523 MB. These are model-process measurements, not whole-PC minimums. The raw evaluation files stay private. Other entries use `None` with an unmeasured code comment; Settings omits their RAM line. Size means the complete pack download in decimal MB; packs add up. No CPU speed or recognition quality was measured in this lane.

`ModelStore::default()` uses the existing `state_dir()`, including its legacy path behavior. Files live in `models/<catalogue-id>/`. `installed_model_paths(id)` returns all files only after a checksum-verified install wrote its completion receipt and every file still has the expected size. It returns `None` for Hex references; the pipeline must query Hex separately. `ModelStore::new(temporary_state)` supports isolated tooling. The pipeline must not run an install on its UI thread.

Downloads run on a worker, stream to `.part`, support Range resume, restart when the server ignores Range, enforce the per-file size cap and SHA-256, and remove checksum failures. A cancellation leaves partial data for resumption. The UI waits for the worker's acknowledgement before enabling another operation. A per-model OS lock serializes install/remove across processes. Downloads follow only HTTPS redirects to explicit Hugging Face/CDN hosts, without cookies, credentials, compression, archives or code execution. A receipt is published only after every file verifies. Network reads time out after three seconds so cancellation can finish on a stalled connection.

Spoken-language preferences are stored separately in `meeting-languages.json`, exposed through `load_meeting_languages` and `save_meeting_languages`. The pipeline configuration lane can consume or migrate that value without changing the model install API. Settings never changes an active route or starts inference.

`stored_bytes(id)` counts catalogue files and their partials so Settings can resume or remove a partial pack after restart. There is no global model quota: packs add up, partials use disk until resumed or removed, and per-file catalogue caps bound each transfer. Cancellation is checked between reads and hash blocks. A stalled read times out after 3 seconds; connection and response-header waits have separate 15 and 20 second limits, so acknowledgement can take longer during setup.

Installed-path discovery is a point-in-time check, not a read lease. The pipeline must handle a model being removed before it opens the returned files, and retry discovery or fall back if opening fails. Removal can fail while a runtime holds files open on Windows. Settings rechecks both completion and stored bytes after every worker result, including a failed removal, so partially removed packs are not labelled installed.
